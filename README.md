# Save Slot

**Save Slot** — статичний локальний інструмент для пошуку ігор, створення власних добірок і ведення backlog-списків. Він працює у браузері, не потребує облікового запису чи окремого сервера та готовий до розміщення на GitHub Pages.

## Можливості

### Пошук і рекомендації

- демонстраційний офлайн-каталог без налаштування;
- необов'язковий пошук у RAWG через власний API key;
- фільтри за платформою, жанром, роком, рейтингом гравців, кількістю голосів і тривалістю;
- окремі режими для коротких ігор, прихованих перлин і найвищих рейтингів;
- випадковий вибір із поточної відфільтрованої добірки;
- пагінація RAWG;
- локальний кеш API-запитів.

### Рейтинги

- рейтинг критиків не використовується;
- RAWG user rating автоматично переводиться у шкалу 0–100;
- підтримується кілька користувацьких джерел рейтингу;
- зведена оцінка враховує кількість голосів у кожному джерелі;
- показується рівень достовірності рейтингу;
- є скориговане сортування, яке не дає кільком голосам витісняти масово оцінені ігри;
- Steam user score можна спробувати отримати з картки гри, але прямий браузерний запит може блокуватися Steam через CORS. У такому разі оцінку можна додати вручну.

### Тривалість

У картці гри передбачено чотири окремі значення:

- HLTB: основний сюжет;
- HLTB: сюжет і додаткове;
- HLTB: повне проходження;
- RAWG average playtime як окремий запасний показник.

HowLongToBeat не має стабільного публічного браузерного API. Тому HLTB-час у статичній версії:

- редагується вручну в картці гри;
- імпортується масово з JSON або CSV;
- не підміняється значенням RAWG.

### Локальні списки

- необмежена кількість окремих списків;
- створення, перейменування, дублювання та видалення;
- статуси: заплановано, граю, пройдено, 100%, відкладено, покинуто;
- пріоритет 1–5;
- особиста оцінка;
- нотатки;
- ручний порядок;
- статистика кількості ігор і загального часу;
- локальне автозбереження через IndexedDB із резервним fallback у localStorage.

### Імпорт та експорт

- резервна копія всіх списків і налаштувань у JSON;
- експорт лише активного списку;
- CSV для таблиць;
- імпорт із заміною або об'єднанням;
- підтримка старого формату `save-slot-list` версії 1;
- RAWG API key навмисно не записується в експортований файл.

### Інтерфейс

- мінімалістична темна піксельна стилістика;
- картки у формі картриджів;
- 3D-нахил залежно від положення курсора;
- регульована сила нахилу;
- режим зменшених анімацій;
- адаптація для телефонів;
- PWA та офлайн-кеш оболонки застосунку.

## Локальний запуск

Через ES-модулі сторінку потрібно відкривати через локальний HTTP-сервер, а не напряму як `file://`.

```bash
python -m http.server 8080
```

Після цього відкрити:

```text
http://localhost:8080
```

Або через Node.js:

```bash
npx serve .
```

## RAWG

1. Створити API key на [RAWG API Docs](https://rawg.io/apidocs).
2. Відкрити **Налаштування** у Save Slot.
3. Обрати `RAWG API`.
4. Вставити ключ і натиснути **Перевірити**.
5. Зберегти налаштування.

Ключ зберігається лише локально у браузері. Репозиторій та JSON-резервні копії його не містять.

## Формат HLTB CSV

Підтримуються українські й англійські назви колонок. Найпростіший формат:

```csv
title,platform,main,mainPlus,completionist
Jeanne d'Arc,PSP,34,42,52
Koudelka,PlayStation,12,14,17
```

Також розпізнаються колонки `name`, `main story`, `main + extras`, `100%`, `назва`, `платформа`, `сюжет`, `сюжет+`.

## Формат HLTB JSON

```json
[
  {
    "title": "Jeanne d'Arc",
    "platform": "PSP",
    "main": 34,
    "mainPlus": 42,
    "completionist": 52
  }
]
```

Можна також передати об'єкт із масивом `games`.

## Тести

Залежності не потрібні. Використовується вбудований Node.js test runner.

```bash
npm test
npm run check
```

Перевіряються:

- нормалізація рейтингів RAWG;
- агрегація кількох джерел;
- фільтрація за HLTB;
- міграція старого формату;
- об'єднання резервних копій.

## GitHub Pages

У репозиторії є готовий workflow `.github/workflows/pages.yml`. Коли репозиторій буде готовий до публікації:

1. Відкрити **Settings → Pages**.
2. У полі **Source** обрати **GitHub Actions**.
3. Зробити push у `main` або вручну запустити workflow `Deploy GitHub Pages`.

Для приватного репозиторію доступність Pages залежить від тарифу GitHub. До відкриття репозиторію застосунок можна запускати локально.
